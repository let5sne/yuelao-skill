## 关于这个分支

客户端 skill 的原始作者是 [@zwbao](https://github.com/zwbao)（[hongniang-skill](https://github.com/zwbao/hongniang-skill)，MIT）。
本仓库在此基础上：

- **新增了完整的后端**（原项目的后端未开源）—— 两层匹配引擎、15 个 API 端点、
  双向同意状态机、279 项服务端测试（含 IDOR / 越权 / 数据泄露的安全断言）。
  后端自 0.5 起维护在独立的私有仓库，本仓库只包含 Skill、CLI 与官网；
  CLI 默认连接公共实例 `https://yuelao.ciyuanlife.cn`
- **实现了技术报告路线图里的第二层**：双塔向量交叉打分（`score = sim(A.seek,B.offer) × sim(B.seek,A.offer)`），
  而非原文描述的档案相似度
- **修了客户端若干 bug**：`sync` 把后端故障静默降级为"没有数据"、拉取失败清空本地快照、
  档案合并打乱数组顺序等
- **改名为「月老 / yuelao」**，与服务地址统一（详见 [CHANGELOG](CHANGELOG.md)）

> **内测中：** 当前为小范围内测阶段，数据库中有部分测试账号，匹配到时会显示标记。

## 架构

```
你的机器                                             服务器
┌──────────────────────────────┐                   ┌──────────────────────────────┐
│                              │                   │                              │
│   私人月老 (Agent Skill)      │                   │   月老匹配后端 (私有仓库)     │
│                              │                   │                              │
│   ┌────────────────────────┐ │    REST API       │   ┌────────────────────────┐ │
│   │ 对话 → 了解你是谁      │ │ ───────────────→  │   │ SQL 预筛 (毫秒)        │ │
│   │ 筛选 → 后端给几条,     │ │                   │   │ 向量粗排 (秒级)         │ │
│   │        我只给你看最多3个│ │ ←───────────────  │   │ 打分层 (可选, 秒级)      │ │
│   │ 传话 → 帮你问,帮你答  │ │                   │   │                        │ │
│   │ 引导 → 你真正要什么    │ │    反馈闭环        │   │ 自进化: 设计目标        │ │
│   └────────────────────────┘ │ ───────────────→  │   │ 尚未生效(无反馈数据)     │ │
│   yuelao CLI + 本地状态    │                   │   └────────────────────────┘ │
│   对话记录只在这里,不发后端    │                   │   只有结构化画像,没有对话     │
│                              │                   │                              │
└──────────────────────────────┘                   └──────────────────────────────┘
```

**核心创新：每个用户都有一位专属的私人月老。** 她不是后端 API 的壳——她有自己的判断力。

后端匹配引擎基于结构化档案做粗筛，但本地月老在对话中积累了大量档案里写不出来的信息：你的隐性偏好、回避的话题、前后矛盾的地方。后端一轮最多入库 5 条推荐（候选池 20 个用于重排），月老最多展示 3 个她真正觉得合适的。

她的筛选判断会回传给后端，后端从中学习——如果某类推荐总被月老压住，说明匹配逻辑在那个维度上不准。**用户越多，每位月老越聪明。**

> ⚠️ 上面这句是**设计目标，不是已生效的事实**。学习回路需要真实的筛选、决定和约会反馈数据；池子还没有规模时，它一条输入也收不到。别把"越用越准"当成现在的产品能力。

**推荐的列表顺序由第一层（确定性条件打分）决定**，双塔向量分只参与挑选、打分层只产出参考数字——两者都不改变排序。这样"用户看到谁"始终可以追溯到可解释的规则。

### 客户端的设计

判断力归月老（LLM），时序和状态归代码：

- **一个 CLI 统一入口。** 所有后端交互走 `scripts/yuelao`，配置、网络、状态逻辑集中管理。
- **故障不伪装成"没数据"。** `sync` 的每类查询单独记录成败，失败时输出 `partial: true` 和 `errors`，月老会如实说"后台连不上"，而不是"暂时没有新推荐"。
- **本地状态快照。** CLI 记住上次见过的推荐状态、已读消息、筛选记录。`yuelao sync` 一条命令拉取全量数据并直接输出"发生了什么变化"——月老每次打开就知道有什么新消息，不靠猜。
- **流程不变量由代码强制。** "月老先筛选、再展示给用户"不是口头约定：没有筛选记录的推荐无法直接回应。
- **档案增量更新不丢数据。** 字符串数组（爱好/标签/dealbreaker）自动取并集，渐进式补充档案不会覆盖旧信息。

## 安装

> 仓库公开，可直接使用下面的 HTTPS 命令克隆；也可以使用 SSH 地址
> `git@github.com:let5sne/yuelao-skill.git`。

### Claude Code

```bash
git clone https://github.com/let5sne/yuelao-skill.git ~/.claude/skills/yuelao
```

建议目录名用 `yuelao`（SKILL.md 里的路径解析会先试这个位置）；用别的名字也能工作，
但要多走一次 `find` 兜底。

### 其他支持 Agent Skills 的工具

将本仓库克隆到你的 agent 工具的 skills 目录。参考 [Agent Skills 标准](https://agentskills.io/specification)。

### 依赖

- `curl`、`jq` 和 Python 3（使用标准库做严格 UTF-8 校验，无需安装 Python 包）

### 开发

```bash
./tests/run-tests.sh
```

124 项测试，依赖 bash + jq + Python 3，不联网（网络部分用 PATH 前置的假 curl 隔离）。覆盖档案合并语义、`sync` 的 diff 与快照更新、异常响应校验、UTF-8 前置校验、ID 类型处理、匹配资格透出、推荐移除通知、收发合并的传话记录、拉黑与主动要推荐，以及"先筛后展"不变量。

CLI 会在输入进入 `jq`、网络请求或本地写入之前拒绝非 UTF-8 字节、`�`（U+FFFD）和 JSON 中孤立的 Unicode 代理项。错误不回显原始输入，也不猜编码或自动补字。遇到错误时，将原始资料保存为 UTF-8 后重试；已经丢失字节的文本需从原始资料重新取得。

## 使用

安装后，对你的 agent 说：

```
月老
```

或者 "我想找对象"、"帮我看看有没有合适的人"。

第一次，月老会跟你聊天——了解你的工作、生活、性格。你甚至不会意识到自己在"建档"。之后每次来，她会检查有没有新进展、新推荐，像一个真正在帮你操心的人。

不知道下一步该说什么？直接问她"你能帮我做什么"。完整的使用说明和常见问题见 **[使用教程](TUTORIAL.md)**。

## 月老能做什么

| 功能 | 说明 |
|------|------|
| **对话式了解你** | 通过聊天建立你的画像 |
| **智能筛选推荐** | 后端粗筛 → 月老细筛，只展示她觉得值得看的 |
| **居间传话** | 双方见面前，月老在中间传话试探，把握分寸 |
| **婚恋认知引导** | 帮你区分短期吸引和长期兼容，看清自己真正要什么 |
| **约会跟进** | 交换联系方式后跟进，反馈给引擎持续优化 |
| **暂停/恢复** | 在发展一段关系？暂停匹配，想回来随时说 |

## 隐私

说清楚哪些数据在哪里，不夸大：

- 你和月老的**对话原文只存在你的本地设备上**，不发到匹配后端。
- 上传到服务器的是**结构化画像**（年龄、城市、性格标签等，不含姓名）、月老的筛选理由和你通过月老传的话。
- **联系方式平时只存本地**；双方都同意匹配后，才会经服务器中转交换给对方。
- 随时可以注销（`yuelao profile delete`），删除服务器档案和全部本地数据。

**"不发到匹配后端"不等于"绝不离开你的设备"，这两件事别混：**

- 月老本身跑在你自己的 agent 里，你和她的对话会经过**你所用的模型服务**。那条链路由你选的工具和厂商决定，我们不控制，也不该假装它不存在。
- **结构化画像会发给外部服务**：计算向量用的 embedding 服务一定会用到；判断打分层开启时，也会把同样的结构化字段发给 TypeSafe。两者都只发结构化字段，不发对话原文。
- 判断打分层记录**当时喂进模型的那份裁剪后档案快照**（`judgment_meta.input_state`）用于事后解释分数。它随推荐级联删除，且**不会出现在任何 API 响应里**。

端到端加密的联系方式与传话中转（服务器"看不了"而不只是"不看"）在路线图中，见[技术报告](TECHNICAL-REPORT.md)。

## 月老的认知框架

月老不是随便配对的算法。她有自己的婚恋认知体系：

- **关系是长期复利资产** — 短期吸引容易量化但无法预测十年后。品格、价值观和生活节奏的兼容才是长期信号
- **品格高于条件** — 诚实、情绪稳定、善良——这些在长期关系中的权重远大于学历和收入
- **想找到对的人，先成为对的人** — 月老帮你匹配，也帮你在对话中看清自己
- **伴侣是彼此的雕塑家** — 好的匹配不仅是"合适"，更是"让彼此变得更好"
